Projects

This page is a selection of software, tools, experiments, and long-running ideas that I have built or continue to explore.

Some of these projects started years before the current generation of AI-assisted development. In several cases, AI has allowed me to revisit older designs, improve them, explore alternatives, and move them forward much more effectively as a single engineer.

The purpose of this page is not to present a chronological résumé. It is to show the kind of software I like to build: native applications, graphics systems, game technology, development tools, compiler-related work, and lower-level experiments.

Graphics, Game Technology and Native Applications

Lienzo

A native image-editing application project focused on desktop graphics, image manipulation, selections, layers, tools, effects, and a traditional desktop workflow.

Areas: C++, Qt, image processing, desktop UI, graphics tooling.

SaruSDL3 / SaruGL

Graphics and game-framework work built around SDL3 and native rendering APIs, with emphasis on understanding and controlling the rendering pipeline rather than hiding it behind a large engine.

Areas: C++20, SDL3, OpenGL, rendering architecture, 2D/3D graphics, input, audio, shaders.

Game and Engine Experiments

Personal work around custom game engines, rendering, gameplay systems, asset handling, input, audio, and the infrastructure required to build games from lower-level components.

Areas: C++, OpenGL, SDL, game architecture, graphics programming.

Compilers, Toolchains and Language Work

GCC / MinGW Toolchain Builder

A toolchain-building project focused on constructing reusable GCC/MinGW environments and automating the otherwise repetitive process of preparing compiler components and supporting tools.

Areas: GCC, binutils, GDB, Make, MSYS2/MinGW64, Python, PySide, build systems.

Areas: compilers, LLVM, native code generation, ABI, language design.

Experiments and Ongoing Work

Not everything I build is intended to become a finished product. Some projects exist specifically to understand a technology, reproduce an idea from first principles, compare approaches, or develop a reusable component for future work.

I consider those experiments an important part of engineering. A small graphics test, compiler prototype, build tool, parser, or systems experiment can be valuable even when its main purpose is to make a difficult subject concrete.

As projects become ready to publish, this page can point to their source repositories, documentation, screenshots, technical notes, and downloadable builds.

AI and These Projects

AI-assisted development is part of my current workflow, but it is not the origin of my engineering experience or of many of the ideas shown here.

I use AI as a technical collaborator and force multiplier: to examine alternatives, accelerate repetitive work, revisit older designs, learn unfamiliar details, and increase what I can realistically build and maintain as one engineer.

The engineering responsibility remains mine: architecture, constraints, technical judgment, verification, testing, debugging, and deciding whether a solution is actually correct and useful.

My broader position on this is described on the About / Information page.
